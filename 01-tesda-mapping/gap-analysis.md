# Competency Gap Analysis

The Cisco CyberOps activities should be evaluated against the TESDA requirements rather than assumed to cover every element.

## Likely Strong Areas

These areas are naturally compatible with CyberOps laboratory work:

- alert handling
- log analysis
- network traffic analysis
- security monitoring
- incident investigation
- IOC identification
- malware analysis
- security reporting

## Areas Requiring Deliberate Evidence

Pay particular attention to:

### ICT251312

- formal case follow-up
- escalation of failed security actions
- stakeholder notification
- reporting spread/lateral movement
- reporting ingress/egress activity

### ICT251313

- defined scanning scope
- scan scheduling
- asset inventory
- documented vulnerability scanning
- formal scan report

### ICT251314

- CTI source validation
- IOC counter-checking
- IOC applicability to infrastructure
- checking running processes/configurations
- containment
- continuous monitoring
- recovery/rollback
- secondary scanning
- mitigation documentation

### ICT251315

Build a dedicated vulnerability-management workflow if the Cisco labs do not provide sufficient evidence for:

1. asset identification
2. vulnerability identification
3. prioritization
4. remediation/control
5. validation
6. reporting

## Portfolio Principle

A documented gap is better than an unsupported competency claim. If a Cisco lab does not demonstrate a requirement, add a controlled supplementary exercise.
